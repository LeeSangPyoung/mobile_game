# 일기토 → 본편 통합 규격

`duel_v2.html`(일기토)을 본편 `prototype.html`에 붙이기 위한 확정 규격.
설계 논의에서 정해진 것만 적는다. 아직 구현되지 않았다.

관련: `duel_link.html`(흐름 시제품), `docs/duel_character_spec.md`(장수 규격)

---

## 0. 현재 상태

| | 상태 |
|---|---|
| 일기토 쪽 다리 (`?embed=1`, postMessage) | **완성** — `duel_v2.html` |
| 흐름 시제품 | **완성** — `duel_link.html` (419줄, 실제로 돌아감) |
| 본편 쪽 배선 | **미착수** — `prototype.html`에 iframe·postMessage 0개 |
| 장수 id 공간 | **일치** — 일기토 49명 전원이 본편 로스터에 존재 |

---

## 1. 발생 조건

- **캠페인 스테이지 전투 중에만** 발생. 멀티대전·무한모드에는 없다.
- 신청 주체는 **적장** — 성의 `_commanderUid`가 배정된 성.
- **교전 중일 때만 신청이 온다.** 판정:
  - 그 성이 공성당하는 중(`_lastSiegeT`가 최근) **또는**
  - 그 성 소속 부대(`homeCastle === 그 성`) 중 `_engaged`인 것이 하나라도 있음
  - 이유: 승리 보상이 전투 내 버프인데, 교전이 없으면 10초가 허공에 흘러간다.
- **성당 1회**로 제한 (`c._duelDone`). 스테이지에 적장이 최대 5명이라 매번 뜨면 성가시다.
- 일기토를 치를 수 있는 내 장수가 하나도 없으면 **신청 자체가 안 온다.**
  수락할 수 없는 제안은 '거부'밖에 못 고르는 가짜 선택이 된다.

---

## 2. 수락 / 거부

| | 결과 |
|---|---|
| **거부** | **페널티 없음.** 하던 전투 그대로 진행 |
| **수락** | 내 장수 고르기 → iframe 결투 |

거부에 벌금을 붙이면 선택이 아니라 강제가 된다. 일기토는 본편에서 유일하게
손 실력이 결과를 정하는 콘텐츠라, 조작에 자신 없는 유저에게 벌금이 되면 안 된다.

**일기토가 진행되는 동안 전장은 일시정지한다.** iframe이 화면을 덮은 사이에
성이 함락되면 안 된다. 서사적으로도 "그 순간 두 장수가 앞으로 나선다"가 맞다.

## 3. 다리 (이미 구현됨 — `duel_v2.html`)

**본편 → 일기토**
```
./duel_v2.html?embed=1&p=<내장수id>&b=<적장id>&pStar=&pLv=&bStar=&bLv=
```

**일기토 → 본편** (`postMessage`, `{ src:'duel', type, ... }`)

| type | 내용 |
|---|---|
| `ready` | 결투 화면 준비됨 |
| `result` | `{ kind:'win'\|'lose'\|'draw', hap, myHp, foeHp, stats:{hits,guards,justs,clashes,taken} }` |
| `close` | 돌아가기를 눌렀다 |

**본편 → 일기토 (중단)**: `{ src:'host', type:'abort' }`

> `result`에 최다 콤보가 아직 안 실려 있다. `maxCombo`를 추가해야 한다.
> (`duel_v2.html`의 파이터에 `maxCombo` 필드는 이미 있음)

## 4. 보상

### 4-1. 콤보 → 별 (주 보상)

- **콤보 정의**: 맞지 않고 연속으로 꽂은 **유효타** 수. 시간 제한 없음.
  내가 피격당할 때만 0으로 초기화. 가드당한 타격은 안 센다.
  (= `duel_v2.html`의 `comboN` 현재 동작 그대로)
- **전역 자기 최고 기록 하나.** 장수별·난이도별 구분 없음.
- 신기록 N을 세우면 **이전 기록+1부터 N까지 전부 통과한 것으로 계산**해서 별 합계 지급.
  - 첫 판 5콤보 → 1+2+3+4+5 = **★15**
  - 다음 6콤보 → **★6**, 7콤보 → **★7**
  - 이전 기록 이하 재달성 → **없음**
- **승패 무관.** 지든 이기든 무승부든 콤보 기록은 인정한다. 일기토 안의 순수 콤보만 본다.
- **상한 없음.**

> 총량은 성장에 따라 계속 열려 있는 구조다. 성장 배수가 붙으면 상대 체력이
> 늘어(★1+0 138 → 다이아+5 552) 판이 길어지고, 콤보 천장도 11~16에서 43~62로
> 올라간다. 조이고 싶어지면 나중에 상한 한 줄만 얹으면 된다.

### 4-2. 승리 → 등용 확률 상승

- 일기토에서 이긴 **그 적장**의 포로 등용 **충성도 −25**.
- 기존 공식 `recruitChance = 0.98 - loyalty/100` 안에서 움직인다.
  - 여포 80 → 55 : 18% → **43%**
  - 일기토 49명 평균 : 29% → **54%**
- 강한 장수는 여전히 상대적으로 어렵다(여포 43% vs 맹획 67%).
- 서사: 일기토에서 꺾인 장수는 마음이 꺾인다.

### 4-3. 승리 → 사기 붕괴 (전투 내 효과)

**대상**: 일기토를 건 **그 성** + 그 성 소속 부대(`homeCastle === 그 성`).
맵 전체가 아니다 — 지도 반대편 부대까지 사기가 꺾이는 건 설명이 안 된다.

**효과**: `atkMul` · `defMul`에 **×0.7**, **10초**.

걸리는 곳:

| 위치 | 결과 |
|---|---|
| 야전 `dpsB` (`atkMul`) | 적 공격 **30%↓** |
| 야전 `dpsA` 분모 `bDef` | 내 공격 **43%↑** (1/0.7) |
| 공성 반격 `counter` (`cAtk`) | 성 반격 **30%↓** |
| 성벽 파괴 `aPow` 분모 `cDef` | 성벽 **43% 빨리** 깎임 |

합쳐서 10초간 교전 효율 약 **2배**.

**구현 방법** — 배수 필드는 매 틱 재계산되므로 `atkMul`에 직접 쓰면 다음 틱에 지워진다.
별도 필드를 두고 계산 **맨 끝에** 한 겹 곱한다:

```js
// 성에
c._moraleUntil = now + 10000;

// 부대 판정
const dazed = a.homeCastle && a.homeCastle._moraleUntil > now;

// 배수 계산 맨 끝
if (dazed) { atkMul *= 0.7; defMul *= 0.7; }
```

기존 업그레이드·장수 버프 계산을 안 건드리고 얹는 구조. 세이브 구조도 안 바뀐다.

### 4-4. 패배 / 무승부

- **패배**: 페널티 없음. (예전 안의 '내 장수 이번 전투 제외'는 **제거**)
- **무승부**: 없음.

## 5. 사기 붕괴 시각 표현

전에 드로우콜 폭주로 발열·버벅임이 있었던 자리다(`drawGarrisonSoldier` 69%).
**병사를 그리는 비용이 평소와 같아야 한다**가 제1 원칙.

판단용 데모: `_morale_demo.html`

### 확정 조합

| 요소 | 방식 | 추가 비용 |
|---|---|---|
| 비틀거리는 자세 | **미리 구운 8컷 애니메이션** | 병사당 **0** (drawImage 1줄 그대로) |
| 몸 기울기 | 구운 컷에 포함 (`tilt = sin(F) × 0.40`) | **0** |
| 무릎 꺾임 | 구운 컷에 포함 (`sag = (1-cos(F)) × s × 0.16`) | **0** |
| 창백한 색 | 구운 컷에 포함 | **0** |
| 병사별 머리 위 별 3개 | 구운 컷에 포함 (뒤로 돌면 작고 어둡게) | **0** |
| 위치 흔들림 | 좌표에 값만 더함 | **0** |
| 부대 위 별고리 5개 | 타원 궤도, 뒤쪽 별부터 그림 | 부대당 **5** |
| 발밑 보라 오라 | 맥동 | 부대당 **1** |

**총 추가 비용: 부대당 6 드로우콜.** 부대 5개여도 30개.

**쓰지 않는 것**
- 런타임 `ctx.rotate()` — 병사마다 `save/rotate/restore`가 붙어 드로우콜 3배.
  기울기는 굽는 시점에 넣으면 공짜다.
- 돼지꼬리 소용돌이 — 별고리로 충분.

**위치 흔들림 수식**
```js
w = Math.sin(t * 속도 + seed) * 좌우진폭;          // 기본 3
b = Math.abs(Math.sin(t * 속도 * 0.5 + seed)) * 상하진폭;  // 기본 2
ctx.drawImage(sprite, x + w - cx, y - b - cy);      // 속도 기본 6
```
병사마다 `seed`가 달라 위상이 어긋나므로 **대열이 흐트러져 보인다.**

### 성 수비대도 동일

`drawGarrisonSoldier`에도 같은 방식을 적용한다. 일기토를 건 성 자신도 대상이다.
병사가 한자리에 모여 있어 **오히려 더 잘 보인다.**
성 깃발은 축 처져서 흔들린다.

### 스프라이트 굽는 비용

병종 3 × 대장 2 × 변형 3 × 8컷 ≈ **144개**를 더 구워야 한다.
한꺼번에 구우면 프레임이 한 번 튄다 →
**일기토 결과 화면이 떠 있는 동안 미리 굽는다.** 유저는 못 느낀다.

## 8. 적장 포진

### 문제

`pickRandomEnemyGeneral`이 **200명 전체**에서 뽑고 가중치가 `1/(버프합+0.05)`라
**명장일수록 덜 뽑힌다.** 일기토 49명은 전원 수동정의 명장이라, 구조적으로
가장 안 나오는 쪽이었다. 붙여놔도 일기토가 거의 안 뜬다.

### 원칙 — 두 풀을 분리한다

| 풀 | 대상 | 규칙 |
|---|---|---|
| **성 지휘관** (= 일기토 상대) | **일기토 49명** | 아래 축 A·B |
| **포로 목록** (패잔병 3~6명) | **200명 전체** | **지금 그대로 유지** |

포로까지 49명으로 좁히면 200명 도감 수집이 망가진다. 반드시 분리한다.
코드상 두 블록은 이미 나뉘어 있다 — `prototype.html:18119`(지휘관) / `18138`(패잔병).

> 지휘관은 `stageEnemies.push(def)`로 **포로 목록에도 들어간다.**
> 즉 일기토 상대는 클리어 후 포로 화면에 그대로 나오고, 거기에 4-2의
> 충성도 −25가 적용된다.

### 축 A — 어느 장수를 세울까

49명을 **무력 오름차순**으로 줄 세우고, 챕터에 따라 중심이 이동한다.
가우시안 위에 **균등 바닥**을 깔아 '뽀록'을 남긴다.

```js
const FLOOR = 0.14;              // 뽀록 — 어느 챕터에서든 아무나 나올 바닥
const SIG   = 0.26;              // 한 챕터에서 나오는 장수 폭
const p = (ch - 1) / (50 - 1);   // 챕터 진행도 0..1
const c = p * (N - 1);           // 무력 순위상의 중심
const s = N * SIG;
w[i] = Math.exp(-(((i - c) / s) ** 2)) * (1 - FLOOR) + FLOOR;
```

시뮬 결과(2000회):

| 챕터 | 자주 나오는 장수 | 최강5인 | 최약5인 |
|---|---|---|---|
| 1 | 손권(72) 조조(73) 공손찬(76) 사마의(62) | **4.3%** | 28.7% |
| 5 | 황개(73) 장임(74) 마대(76) 우금(72) | 4.0% | 23.6% |
| 15 | 기령(79) 마등(78) 관흥(78) 맹획(79) | 2.4% | 10.9% |
| 30 | 능통(85) 조인(86) 위연(88) 서황(89) | 5.4% | 2.6% |
| 50 | 장비(98) 관우(99) 여포(100) 조운(97) | 29.9% | 4.5% |

바닥이 없으면 챕터 1에서 여포가 영영 안 나오고, 바닥만 있으면 차등이 없다.

### 축 B — 별 등급

`rollStars()`는 지금 `STAR_ODDS`가 **챕터 무관 고정**이다(★1 41% … ★5 3%).
지휘관에 한해 챕터별로 분포를 이동시킨다. **다이아(6)는 전 구간 0% 유지.**

```js
const p = (ch - 1) / (50 - 1);
const c = 1 + p * 3.2;           // 목표 별 중심: 챕터1 ★1.0 → 챕터50 ★4.2
const s = 1.25;
w[st] = Math.exp(-(((st - c) / s) ** 2));   // st = 1..5, 6은 0
```

| 챕터 | ★1 | ★2 | ★3 | ★4 | ★5 | 다이아 |
|---|---|---|---|---|---|---|
| 1 | 62% | 33% | 5% | – | – | 0% |
| 5 | 53% | 39% | 8% | – | – | 0% |
| 15 | 28% | 47% | 22% | 3% | – | 0% |
| 30 | 5% | 27% | 45% | 21% | 3% | 0% |
| 50 | – | 2% | 19% | 47% | 32% | 0% |
| *현재* | *41%* | *30%* | *18%* | *8%* | *3%* | *0%* |

### 두 축이 곱해지면

챕터 1에서 만나는 건 보통 **★1 손권**, 챕터 50에서는 **★4 여포**.
같은 여포라도 초반 뽀록이면 ★1이라 해볼 만하고, 후반이면 ★4~5라 벽이다.
같은 얼굴이 다른 무게로 돌아오므로 49명을 오래 쓴다.

### 조절 손잡이

| 값 | 기본 | 뜻 |
|---|---|---|
| `FLOOR` | 0.14 | 올리면 아무나 더 자주, 내리면 차등이 뚜렷 |
| `SIG` | 0.26 | 좁히면 챕터색이 진해짐 |
| 별 중심 계수 | 3.2 | 끝 챕터의 목표 별(★4.2 근처) |

### 내 장수 쪽

출전 편성(`activeDeployGeneralUids`, 최대 10명)에 **일기토 49명이 하나도 없으면
신청 자체가 안 온다.** 수락할 수 없는 제안은 가짜 선택이다.

> 200명 중 49명이라, 아무 생각 없이 편성하면 10명 중 한 명도 안 걸릴 확률이
> 약 7%다. 나중에 편성 화면에서 일기토 가능 장수에 표식을 달면 자연히 풀린다.
