# 세이브 동기화 — 사용자 테스트 시나리오

[설계](save_sync_design.md) · [유저 시나리오](save_sync_user_story.md) 의 짝.
구현이 끝날 때마다 이 표를 처음부터 다시 훑는다.

> 2판. 1판은 유저가 「계정 연결」 버튼을 누르는 전제였다.
> 지금은 **플레이 게임즈 자동 로그인** 이라, 시험의 초점이
> "유저가 잘 누르는가" 에서 **"유저가 아무것도 안 해도 되는가"** 로 바뀌었다.

## 읽는 법

- **기대**가 곧 합격 기준이다
- ⛔ 는 **하나라도 나오면 배포를 멈춘다**
- 실제 기기 2대로 한다. 에뮬레이터는 PGS·자동 백업 동작이 실기와 다르다

## 준비물

| | |
|---|---|
| A폰 / B폰 | 실기 2대 |
| 구글 계정 2개 | 본인용 + 남 흉내용 |
| PGS 꺼 둔 기기(또는 설정) | 소수 경로 확인용 |
| 서버 콘솔 | `saves` / `accounts` 직접 확인 |

각 시나리오 전에 **세이브 요약을 적어 둔다.**

```
장·절 / 장수 수 / 별 / 골드 / 최고 연타
예) 12장 20절 / 34명 / 210 / 12,400 / 15
```

# A. 신규 회원

**핵심: 아무것도 달라 보이지 않아야 한다.**

### A-1. 첫 실행 — 조용해야 한다 ⭐

| | |
|---|---|
| 절차 | 앱 설치 → 실행 |
| 기대 | 튜토리얼이 지금과 **똑같이** 시작. 로그인 화면·팝업·추가 로딩 **없음** |
| 확인 | `accounts` 에 행 1개. `pgs_id` 채워짐 |
| ⛔ | 로그인 화면이 뜬다 / 시작이 눈에 띄게 느려졌다 / PGS 배너가 게임을 가린다 |

### A-2. 비행기 모드로 첫 실행

| | |
|---|---|
| 절차 | 비행기 모드 → 설치 → 실행 → 튜토리얼 클리어 → 3장까지 |
| 기대 | **평소와 완전히 동일.** 오류 문구 없음 |
| 이어서 | 비행기 모드 해제 → 백그라운드 → 다시 열기 |
| 기대 | 조용히 로그인되고 3장 기록이 올라간다 |
| ⛔ | 네트워크가 없어서 게임이 멈추거나 시작이 지연된다 |

### A-3. 진행 중 동기화

| | |
|---|---|
| 절차 | 1판 클리어 → 서버 `saves.rev` 확인 |
| 기대 | `rev` 상승. `summary` 의 별·골드가 화면과 일치 |
| 이어서 | 장수 강화 1회 → 백그라운드 |
| 기대 | 백그라운드 진입 시 확실히 한 번 올라간다 |
| ⛔ | 10초 안에 여러 판 깼는데 요청이 매번 나간다(묶기 실패) |

### A-4. PGS 없는 기기 — 소수 경로

| | |
|---|---|
| 절차 | 플레이 게임즈를 끈 기기에서 설치 → 실행 → 5장까지 |
| 기대 | **게임은 평소대로.** 익명 계정으로 서버 백업은 된다 |
| 확인 | 설정 → 계정 = 「이 기기에만 저장됨」 + 수동 연결 버튼 |
| ⛔ | 오류가 뜨거나 게임이 진행되지 않는다 |

### A-5. 수동 연결 (A-4 이어서)

| | |
|---|---|
| 절차 | 설정 → 구글 계정으로 연결 |
| 기대 | 연결 완료. 5장 기록이 그 계정으로 묶인다 |
| 이어서 | 로그인 창에서 **뒤로가기**로 취소 |
| 기대 | 조용히 복귀. **미연결 상태 그대로** |
| ⛔ | 로딩이 걸린 채 멈춘다 / 연결된 것처럼 표시된다 |

# B. 기존 회원

**이미 잘 하고 있던 사람.** 여기서 사고가 나면 가장 아프다.
업데이트 전 요약을 **반드시 적어 두고** 시작한다.

### B-1. 업데이트 직후 첫 실행 — 아무 일도 없어야 한다 ⭐

| | |
|---|---|
| 준비 | 구버전에서 12장까지. 요약 기록 |
| 절차 | 신버전 업데이트 → 실행 |
| 기대 | **12장 그대로.** 장수·별·골드·강화 전부 일치. 팝업·선택화면 없음 |
| 확인 | 서버 `saves` 에 올라감. `summary` 가 적어 둔 값과 일치 |
| ⛔ | 진행도가 하나라도 다르다 / 선택 화면이 뜬다 / 초기화됐다 |

> 서버에 그 사람 기록이 없으므로 **충돌이 날 수가 없다.**
> 여기서 선택 화면이 뜨면 로직이 잘못된 것이다.

### B-2. 항목 하나라도 빠지지 않았나 ⭐

| | |
|---|---|
| 절차 | B-1 후 서버 `saves.data` 와 로컬 `localStorage['save']` 비교 |
| 기대 | **문자열이 완전히 동일.** 항목 25개 전부 |
| 특히 | `generals` 의 `lv`(강화), `stars`, `duelBestCombo`, `upgrades`, `formations` |
| ⛔ | 항목이 하나라도 빠졌다 |

### B-3. 익명 → PGS 승격 ⭐

| | |
|---|---|
| 준비 | 1·2단계 배포본에서 12장까지(익명 계정) |
| 절차 | 3단계 배포본으로 업데이트 → 실행 |
| 기대 | **12장 그대로.** 익명 계정이 PGS 계정으로 승격되며 기록을 물려받음 |
| 확인 | `accounts` 행이 늘지 않고, 기존 uid 에 `pgs_id` 가 채워진다 |
| ⛔ | 새 계정이 생겨 기록이 빈 채로 시작된다 |

### B-4. 지웠다 다시 깔기 (같은 기기) ⭐ — 불만 ②

| | |
|---|---|
| 준비 | A폰 12장 |
| 절차 | 앱 완전 삭제 → 다시 설치 → 실행 |
| 기대 | **12장 그대로.** 유저가 아무것도 안 해도 |
| ⛔ | 처음부터 시작된다 |

### B-5. 기기 이동 ⭐ — 불만 ①

| | |
|---|---|
| 준비 | A폰 12장. B폰은 **같은 구글 계정** |
| 절차 | B폰에 설치 → 실행 |
| 기대 | **바로 12장.** 튜토리얼이 뜨지 않는다. 유저 동작 0 |
| 이어서 | B폰에서 13장 클리어 → A폰 실행 |
| 기대 | A폰이 13장으로 따라온다 |
| ⛔ | 튜토리얼이 시작된다 / B폰 기록이 A폰 12장을 덮어쓴다 |

### B-6. 다른 구글 계정 폰

| | |
|---|---|
| 절차 | **다른 구글 계정**을 쓰는 폰에 설치 → 실행 |
| 기대 | 남남이다. 새 계정으로 튜토리얼 시작 |
| ⛔ | 남의 기록이 보인다 |

### B-7. 양쪽에서 따로 진행 — 갈라짐 ⭐

| | |
|---|---|
| 준비 | A·B 둘 다 12장, 같은 계정 |
| 절차 | **둘 다 비행기 모드** → A는 15장, B는 13장 → A만 온라인 → 그다음 B |
| 기대 | B에서 **선택 화면.** 양쪽 요약이 실제와 일치 |
| 이어서 | B에서 「이 기기(13장)」 선택 |
| 기대 | B는 13장 유지. A의 15장은 `save_history` 에 남는다 |
| ⛔ | 묻지 않고 한쪽을 지운다 / 요약 숫자가 실제와 다르다 |

### B-8. 잘못 골랐을 때 되돌리기

| | |
|---|---|
| 절차 | B-7 후 설정 → 기록 되돌리기 |
| 기대 | 7일 내 기록 목록. 15장 기록으로 복구 |

### B-9. 남의 계정을 못 덮어쓴다 ⭐ 보안

| | |
|---|---|
| 절차 | A폰 `uid` 를 알아낸 뒤 **토큰 없이** `/save/put` 직접 호출 |
| 기대 | **401 거부.** 서버 기록 변화 없음 |
| 이어서 | 멀티 `hello` 도 uid 만으로 시도 |
| 기대 | 거부되거나 토큰 발급 유예 경로로만 통과 |
| ⛔ | 남의 세이브를 읽거나 덮어쓸 수 있다 |

### B-10. 복구 코드

| | |
|---|---|
| 절차 | A폰 설정 → 복구 코드 보기 → B폰에 입력 |
| 기대 | B폰이 A폰 기록으로 바뀐다 |
| 이어서 | **같은 코드를 또** 입력 |
| 기대 | 「이미 사용된 코드」 거부 (1회용) |

# C. 험한 상황

### C-1. 동기화 도중 앱 강제 종료

| | |
|---|---|
| 절차 | 클리어 직후(올리는 중) 강제 종료 → 재실행 |
| 기대 | 로컬 기록 온전. 다음 기회에 올라감 |
| ⛔ | 세이브가 깨지거나 비어 있다 |

### C-2. 서버가 죽어 있을 때

| | |
|---|---|
| 절차 | 서버 중지 → 실행 → 3판 진행 → 서버 복구 → 백그라운드 → 재실행 |
| 기대 | 게임은 내내 정상. 복구 후 밀린 기록이 올라감 |
| ⛔ | 시작이 막히거나 오류 문구가 뜬다 |

### C-3. 지하철 — 끊겼다 붙었다

| | |
|---|---|
| 절차 | 네트워크를 30초 간격으로 껐다 켜며 10분 플레이 |
| 기대 | 끊김 없이 플레이. 마지막에 최신 기록이 서버에 있다 |
| ⛔ | 낡은 기록이 새 기록을 덮는다 |

### C-4. 시계가 어긋난 기기

| | |
|---|---|
| 절차 | A폰 시각을 하루 뒤로 → 진행 → 동기화 |
| 기대 | `rev` 로 판정하므로 정상. **시각은 표시용으로만** |
| ⛔ | 시각 비교로 최신을 판정해 낡은 쪽이 이긴다 |

### C-5. 세이브가 큰 유저

| | |
|---|---|
| 절차 | 장수 300명 + 500장 클리어 상태로 동기화 |
| 기대 | 정상. 30KB 안팎 |
| ⛔ | 상한(256KB)에 걸리거나 눈에 띄게 느리다 |

### C-6. 웹↔앱

| | |
|---|---|
| 절차 | 앱에서 12장 → 웹(`app.wooriban.org`)에서 같은 구글 계정 로그인 |
| 기대 | 웹에서 12장 이어짐. 반대도 동일 |

# D. 배포 전 최종 점검

**하나라도 실패하면 내보내지 않는다.**

| # | 항목 | 시나리오 |
|---|---|---|
| 1 | 기존 유저가 업데이트해도 **진행도 그대로** | B-1 |
| 2 | 세이브 항목이 **하나도 안 빠진다** | B-2 |
| 3 | 지웠다 깔아도 **이어진다** | B-4 |
| 4 | 폰을 바꿔도 **유저 동작 없이 이어진다** | B-5 |
| 5 | 남의 세이브를 **못 건드린다** | B-9 |
| 6 | 신규 유저가 **로그인 화면을 안 본다** | A-1 |

## 단계별로 어디까지

| 배포 | 시나리오 |
|---|---|
| 1단계 (익명 + 서버 세이브) | A-1~A-3, **B-1, B-2**, B-9, C-1~C-4 |
| 2단계 (네이티브 토큰) | 위 전부 + **B-4** |
| 3단계 (플레이 게임즈) | 위 전부 + A-4, **B-3, B-5~B-8** |
| 4단계 (뒷문) | 위 전부 + A-5, B-10, C-6 |

1단계 배포에도 **B-1·B-2 는 반드시 돈다.** 기존 유저 27명의 기록이 걸려 있다.
